## Bug matrix

### 1. Battle opened a screen instead of a combat mode
- **Root cause** — `beginCommandCombat` disabled the command input (`input.disabled = true`)
  and offered no visible action controls, so the only way to act was to wait for
  narration and then type "attack". The action buttons lived in `#combat-panel`,
  which is permanently `hidden`/`inert`.
- **Files / functions** — `index.html` (`#combat-status`), `stabilization-v7211.js`
  (`beginCommandCombat`, `finishCommandCombat`, `startCombat`, `updateEnemyHUD`), `styles.css`.
- **Fix** — Added an inline `#combat-actions` group inside the existing game
  interface with Attack, Healing Spell, Multiple Strike, Shock Spell, Items,
  Defend and Flee. New `Game.runCombatCommand` / `bindCombatActionButtons` /
  `updateCombatActionAvailability` route buttons, keyboard, typed commands,
  TalkBack and voice through the single `Game.processCommand` engine. The command
  input is never disabled during combat, and stale text is cleared on entry and exit.
- **Tests** — 01–05.

### 2. Combat internals leaked into narration
- **Root cause** — Spell modules narrated mastery telemetry: "efficiency XP",
  "efficiency damage", "Multi Strike: N hit(s), N blocked, N damage, N MP".
- **Files** — `spell-mastery-black-sword.js`, `cemetery-spellfield-combat-v11.js`,
  `expansive-forest-multitarget-v13.js`, `fair-group-combat-v14.js`, `stabilization-v7211.js`.
- **Fix** — Telemetry lines removed from player-facing output; the underlying
  mastery/efficiency mechanics still record internally. Narration is now natural
  ("The light from your hands strikes for 69 damage.", "Your shock spell failed.").
- **Tests** — 06, 07, 28.

### 3. Finite area kill quotas ("9 monster types left", "still hunted here")
- **Root cause (source of truth)** — `Game.getEnemyQuota` + `Game.getLivingEnemies`
  formed a finite per-area ledger; `hunt-clear-v19.js#recordDefeatedForArea`
  narrated "N more X needed here" after each kill, `showLivingEnemies` printed
  "N remaining / fully defeated", `enterLocation` announced a cleared pack, and
  `getRandomEncounterPool` filtered against the quest ledger.
- **Files / functions** — `game.js` (`getAreaMonsterPool` [new], `getRandomEncounterPool`,
  `showLivingEnemies`, `enterLocation`, hunt branch), `hunt-clear-v19.js`,
  `hunt-wayfinder-v21.js`.
- **Fix** — Introduced `getAreaMonsterPool(locId)`: the area's configured list is a
  **pool of monster TYPES**, never a stock of remaining monsters. Random encounters
  and hunting both use it, so the same forest can be farmed indefinitely. Only a
  genuinely slain unique boss/final boss is excluded. `recordDefeatedForArea` still
  records kills for quests/achievements but narrates nothing. All remaining-count
  strings are gone.
- **Tests** — 08–11.

### 4. Duplicate monster announcements
- **Root cause** — Already partly solved by `MonsterGroupFormatter`; verified and locked.
- **Fix** — Regression-locked grammar for 1/2/3+, irregular plurals ("goblin witches",
  "wild boars") and mixed groups, and proved the visual log and TTS use one identical
  grouped string emitted exactly once.
- **Tests** — 12, 13.

### 5. "More Frequent Monster Encounters" was not a real setting
- **Root cause** — Only reachable via the typed `encounters on/off` command, which set
  `sacred.encounterMode`; there was no UI control and no persistence.
- **Files** — `stabilization-v7211.js` (`EncounterSettings` [new]), `sacred.js`
  (`randomEncounterEligibility`, `enterLocation`, group sizing), `index.html`.
- **Fix** — Real persisted setting with two profiles that the scheduler consumes
  directly: OFF `{threshold 5, cooldown 90s, chance 0.06, group 1–3}`, ON
  `{threshold 3, cooldown 45s, chance 0.18, group 2–5}`. Both keep a cooldown, so
  encounters never fire on every movement. Exposed as an accessible checkbox in
  Settings and persisted to `localStorage`.
- **Tests** — 14–16.

### 6. Settings did not actually turn systems off
- **Root cause** — `playVoice` accepted a `force: true` bypass (used by the TTS
  diagnostic and chat voice test), and battle-track continuation in
  `handleTrackEnded` did not re-check `musicEnabled`.
- **Files** — `music.js` (`playVoice`, `handleTrackEnded`, new `setMusicEnabled` /
  `setSFXEnabled` / `setVoiceEnabled`), `online.js` (`speakText`, `testSelectedVoice`).
- **Fix** — Application TTS OFF is now absolute: no `SpeechSynthesis` call can be
  forced. Music OFF blocks world, battle, victory and layer starts. SFX OFF blocks
  every effect path. All three persist. Application TTS is documented as separate
  from Android TalkBack, which the game neither controls nor disables.
- **Tests** — 17–22.

### 7. Music preservation
- No track, playlist or licence was removed. Verified that all contexts
  (exploration, city, forest, battle, boss, final boss, victory) still resolve
  tracks, that battle playlists avoid immediate repeats and keep rotating, and that
  battle music is selected independently of world music with proper restore.
- **Tests** — 23–25.

### 8. Shock / Multiple Strike / Healing fairness
- **Root cause** — Shock had no entry in the centralized `GameSpellSystem`; it fell
  through to older modules with no failure model and telemetry narration.
- **Fix** — Added `GameSpellSystem.castShock` with the three-outcome fair model
  (success / block / failure), cost, cooldown and synchronized SFX. Multiple Strike
  and Healing narrations reworded to the required natural strings, including
  "Your health is already full." Invalid casts consume nothing.
- **Tests** — 26–30.

### 9. Door-opening magic
- Verified the configured-door model: Multiple Strike breaks only a door with
  `canBeBrokenByMultipleStrike`, an already-open door costs nothing, and a location
  with no door target costs nothing.
- **Test** — 31.

### 10. Death and temple restoration
- **Root cause** — `performTempleRescue` narrated a technical restoration line.
- **Fix** — Now narrates exactly "You have died." → "You awaken in the temple." →
  "The temple restores your health and magic.", with HP/MP set to full and no
  per-point tick narration.
- **Test** — 32.

### 11. Regeneration spam
- **Root cause** — `applyTimedRegeneration` announced "+N HP and +N MP", and
  `enemyGroupTurn` announced "Battle recovery: +1 HP, +1 MP" every round.
- **Fix** — Passive regeneration is silent, capped at maximum, and the per-round
  battle-recovery line is removed.
- **Test** — 33.

### 12. Economy
- Audited every currency mutation path. `RewardEconomy.settleBattle` is the single
  authoritative, idempotent settlement keyed by battle transaction ID; the ledger is
  persisted in the save so it survives reload/reconnect. Verified that typing
  "attack" — once, ten times, double-clicked, or button plus command — grants no
  currency, that repeat settlements return `duplicate: true` with an unchanged
  wallet, and that premium currency stays rare and explicit (no diamonds from
  common kills, pity ≥ 20 victories).
- **Tests** — 34–37.

### 13. Inventory
- **Fix** — Added `Game.examineInventoryItem` and `Game.showInventoryItemDetails`,
  and surfaced Use / Examine / Details buttons in both inventory renderers.
  `useItem` now validates before consuming: quest items are never consumed, full
  HP/MP refuses the item, and combat-only items are refused outside battle.
- **Tests** — 38–41.

### 14. Hero information privacy
- **Fix** — Added a real server-projection allowlist, `OnlineSystem.PUBLIC_HERO_FIELDS`
  + `toPublicHero`, applied before hero data reaches the UI. Account ids, emails,
  player codes, PIN hashes, tokens, secret answers and internal UUIDs are stripped —
  not merely hidden with CSS.
- **Tests** — 42, 43.

### 15. Repeated "Online / Google linked" announcements
- **Root cause** — `updateIndicators` rewrote the `aria-live` status text on every
  call (every render, movement, battle and chat refresh), re-firing the live region;
  `announceToPlayer` had no change detection.
- **Fix** — Fixed at the source: status text is only written when it actually
  changes, and announcements are de-duplicated so only material changes (login,
  connection restored/lost, hero switched) are spoken. No blanket debounce timers.
- **Tests** — 44, 45.

### 16. Chat — five-minute expiration kept
- Unchanged and re-verified: the expiry is set and enforced by the database
  (`expires_at = created_at + interval '5 minutes'`, immutable timestamps, RLS
  `expires_at > now()`), not by client-side hiding.
- **Test** — 46.

### 17. Chat first-use community notice
- **New** — `chat-notice-feedback-v7221.js` + an accessible `role="dialog"` notice.
  Shown once, before the first send, in both Chat Rooms and Direct Chat; the
  acknowledgment is stored per user and it is never shown again.
- **Tests** — 47, 48.

### 18. Chat moderation
- Server-side moderation (`moderator_roles`, `is_game_moderator`) preserved and
  re-verified; client filtering remains an addition, not the authority.
- **Test** — 49.

### 19. Feedback entry point
- **New** — A visible "📣 Send Feedback" button in Chat Rooms and Direct Chat, plus a
  feedback panel supporting bug reports, player/message reports, feature
  suggestions, accessibility issues and general feedback. It submits through the
  existing protected `submit_game_feedback` RPC with duplicate-send prevention.
- **Tests** — 50–53.
